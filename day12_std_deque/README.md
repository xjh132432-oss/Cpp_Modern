# Day12｜std::deque

## 1. 学习目标

本日学习 C++ 标准库中的 `std::deque`（双端队列），理解其底层存储结构、常用操作，以及与 `std::vector`、`std::list` 的区别。

核心目标：

- 掌握 deque 的头部和尾部插入、删除操作。
- 理解 deque 支持随机访问的原因。
- 理解 vector、list、deque 三种容器的适用场景。

## 2. 学习内容

### 2.1 deque 基础操作

头文件：

    #include <deque>

常用接口：

| 函数 | 作用 |
|---|---|
| `push_back(x)` | 尾部插入 |
| `push_front(x)` | 头部插入 |
| `pop_back()` | 删除尾部元素 |
| `pop_front()` | 删除头部元素 |
| `front()` | 获取首元素 |
| `back()` | 获取尾元素 |
| `size()` | 获取元素数量 |
| `empty()` | 判断容器是否为空 |
| `operator[]` | 下标访问 |
| `at()` | 带边界检查的下标访问 |

### 2.2 随机访问

deque 支持：

    d[2];
    d.at(2);

两者都可以访问第三个元素。

区别：

- `operator[]` 不进行边界检查。
- `at()` 进行边界检查，越界时抛出 `std::out_of_range` 异常。

### 2.3 双端插入与删除

使用 `push_front()` 和 `push_back()` 可以分别在两端插入元素。

使用 `pop_front()` 和 `pop_back()` 可以分别删除两端元素。

需要注意：

- `pop_front()` 和 `pop_back()` 不返回被删除的元素。
- 调用删除操作前，应确保 deque 非空。
- 连续调用 `push_front()` 时，新元素会始终插入当前第一个元素之前。

### 2.4 deque 的底层结构

deque 采用分段连续存储结构。

- 元素分布在多个连续内存块中。
- 内部通过映射结构管理这些内存块。
- 可以根据索引定位对应内存块及块内位置，因此支持 O(1) 随机访问。
- 两端可以通过管理内存块实现高效扩展，不需要像普通连续数组那样整体搬移所有元素。

因此 deque 能够同时支持随机访问和高效的头尾插入、删除。

## 3. 三个实验

### 实验一：deque 基础操作

创建：

    std::deque<int> d{10, 20, 30, 40, 50};

完成：

- 使用 `push_front()` 插入 5。
- 使用 `push_back()` 插入 60。
- 输出 `front()`、`back()`。
- 使用 `[]` 和 `at()` 访问第三个元素。
- 使用迭代器遍历。

实验输出：

    front: 5
    back: 60
    30 30
    5 10 20 30 40 50 60

### 实验二：双端插入与删除

完成：

- 连续两次头部插入 2、1。
- 连续两次尾部插入 60、70。
- 连续两次删除头部元素。
- 删除一次尾部元素。
- 遍历输出最终结果。

实验输出：

    10 20 30 40 50 60

### 实验三：vector、list、deque 对比

分别创建三个容器，初始内容为：

    {10, 20, 30, 40, 50}

完成：

- 头部插入 5。
- 尾部删除一个元素。
- 使用下标访问第三个元素，验证随机访问能力。
- 遍历三个容器，比较最终内容。

实验中发现：

- vector 支持下标随机访问。
- deque 支持下标随机访问。
- list 不支持 `operator[]`，需要通过迭代器访问。

list 第三个元素的访问方式：

    *std::next(l.begin(), 2)

需要包含 `<iterator>`。

三个容器最终内容：

    5 10 20 30 40

## 4. 三种容器对比

| 对比 | vector | list | deque |
|---|---|---|---|
| 底层结构 | 连续内存 | 双向链表 | 分段连续内存 |
| 随机访问 | O(1) | O(n) | O(1) |
| 头部插入 | O(n) | O(1) | O(1) |
| 尾部插入 | 均摊 O(1) | O(1) | O(1) |
| 已知位置中间插入 | O(n) | O(1) | O(n) |
| 头部删除 | O(n) | O(1) | O(1) |
| 尾部删除 | O(1) | O(1) | O(1) |

注意：list 在已知位置插入和删除时效率较高，但查找位置仍然可能需要 O(n)。不能仅凭单项操作复杂度判断容器整体性能。

## 5. 本日总结

Day12 学习了 deque 的基础 API、双端操作和随机访问能力。

本日最重要的知识是理解三种容器的底层结构：

- vector：连续内存，适合随机访问和尾部添加。
- list：双向链表，适合已知位置的频繁插入和删除。
- deque：分段连续存储，兼顾随机访问和两端操作。

容器的选择应结合实际操作需求，而不是只看某一项操作的时间复杂度。

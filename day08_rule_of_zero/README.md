# Day08：Rule of 0 / 3 / 5 与特殊成员函数

## 一、学习目标

理解 C++ 特殊成员函数的生成规则，掌握 `=default`、`=delete` 的使用方法，理解 Rule of 0 / 3 / 5，以及拷贝操作与移动操作之间的关系。

## 二、核心知识

### 1. 六种特殊成员函数

- 默认构造函数：默认初始化对象。
- 析构函数：对象生命周期结束时执行清理。
- 拷贝构造函数：使用已有对象初始化新对象。
- 拷贝赋值运算符：将已有对象的状态赋给另一个已存在的对象。
- 移动构造函数：使用右值初始化新对象，允许成员转移资源。
- 移动赋值运算符：将右值对象的资源或状态转移给已有对象。

### 2. Rule of 0

优先使用 `std::string`、`std::vector` 等能够自行管理资源的类型，避免手动管理内存和编写不必要的特殊成员函数。

当类的成员已经能够正确处理复制、移动和销毁时，通常可以直接使用编译器生成的特殊成员函数。

### 3. Rule of 3

当类需要自行管理资源时，重点考虑：

- 析构函数；
- 拷贝构造函数；
- 拷贝赋值运算符。

原因是资源的释放、复制新对象和赋值给已有对象必须相互协调，避免浅拷贝、重复释放等问题。

### 4. Rule of 5

C++11 引入移动语义后，还需要考虑：

- 移动构造函数；
- 移动赋值运算符。

对于确实需要自行管理资源的类，应综合设计资源的复制、移动和销毁行为。

### 5. `=default`

显式要求编译器提供相应的默认实现。

例如：

    Student() = default;

`=default` 不保证函数一定可用。如果成员类型无法执行相应操作，该函数仍可能被定义为删除状态。

### 6. `=delete`

明确禁止调用某个函数。

例如：

    Student(const Student&) = delete;
    Student& operator=(const Student&) = delete;

这两行分别禁止拷贝构造和拷贝赋值。调用相应操作时，编译器会报错。

### 7. 特殊成员函数的生成规则

- 用户声明拷贝构造函数或拷贝赋值运算符后，编译器不会隐式声明移动构造函数和移动赋值运算符。
- 用户声明析构函数后，编译器不会隐式声明移动构造函数和移动赋值运算符。
- 用户声明移动构造函数或移动赋值运算符后，隐式生成的拷贝构造函数和拷贝赋值运算符会被定义为删除状态。
- 显式使用 `=default` 可以请求默认实现，但不能绕过成员类型本身的限制。

### 8. `std::move`

`std::move` 本身不执行资源移动，而是将表达式转换为右值形式，使其能够参与移动重载的匹配。

是否真正发生移动，取决于类型是否提供可用的移动操作，以及重载决议的结果。

移动后的对象通常仍然有效，但其状态可能未指定，不能假定 `std::string` 移动后一定为空。

## 三、实战验证

使用 `Student` 类完成以下实验：

1. 使用 `std::string` 和 `int` 成员，不手写特殊成员函数，验证拷贝构造、拷贝赋值和移动构造。
2. 添加 `Student(const Student&) = delete`，验证拷贝构造被禁止。
3. 验证声明拷贝构造函数后，默认构造函数不会再被隐式声明。
4. 添加 `Student() = default`，恢复默认构造能力。
5. 显式删除拷贝构造和拷贝赋值，同时将移动构造和移动赋值声明为 `=default`，验证对象可以移动但不能复制。
6. 恢复简洁的 Rule of 0 实现，理解普通业务类为什么通常不需要手写特殊成员函数。

## 四、总结

Day08 的核心不是记住每条语法，而是理解类的特殊成员函数之间存在生成规则和依赖关系。

优先采用 Rule of 0；只有在确实需要自行管理资源时，才进一步考虑 Rule of 3 / 5。

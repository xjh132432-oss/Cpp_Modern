## 核心知识

### 1. 迭代器基础

- `begin()`：返回指向第一个元素的迭代器。
- `end()`：返回指向尾后位置的迭代器，不能解引用。
- `*it`：访问迭代器指向的元素。
- `auto`：让编译器自动推导迭代器类型。

### 2. vector 的迭代器失效规则

- 尾部插入未触发重新分配时，原有元素迭代器仍然有效，但原来的 `end()` 失效。
- 尾部插入触发重新分配时，所有原有迭代器和引用失效。
- `reserve()` 的参数大于当前容量时，会重新分配存储空间，原有迭代器和引用失效。
- `reserve()` 未改变容量时，不会使现有迭代器失效。

### 3. 内存重新分配

`std::vector` 使用连续存储空间。当需要扩大容量时，可能申请新的存储空间并搬迁已有元素。重新分配后，旧迭代器不能继续用于访问元素。

### 4. 安全遍历

修改容器后，应根据操作的失效规则判断原迭代器是否仍然有效。必要时重新获取 `begin()` 和 `end()`，避免继续使用失效迭代器。

## 实验总结

通过三个独立实验，观察了预留容量后的尾部插入、主动触发重新分配，以及修改容器后重新获取迭代器的遍历方式。

本日重点是理解：**迭代器的有效性取决于容器操作及其失效规则，不能仅凭程序输出正常就判断迭代器仍然有效。**

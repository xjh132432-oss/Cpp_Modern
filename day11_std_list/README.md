# Day11｜std::list

## 1. 学习目标

本日主要学习 C++ 标准库中的 `std::list`，理解双向链表的基本结构、常用操作，以及它与 `std::vector` 在迭代器失效规则和使用场景上的区别。

## 2. 学习内容

### 2.1 list 基础操作

- 使用 `std::list<int>` 创建双向链表。
- `push_back()`：在末尾添加元素。
- `push_front()`：在开头添加元素。
- `front()`：访问第一个元素。
- `back()`：访问最后一个元素。
- `size()`：获取元素数量。
- 使用迭代器遍历链表。

实验结果：

    size: 5
    5 10 20 30 40
    front: 5
    back: 40

### 2.2 list 的插入与删除

- `insert()`：在指定迭代器位置之前插入元素。
- `erase()`：删除指定位置的元素。
- `erase()` 会返回被删除元素的下一个迭代器。
- 删除过程中可以利用返回值继续遍历，避免访问已经失效的迭代器。
- `list` 插入其他节点不会使已有迭代器失效。
- `list` 删除节点只会使指向被删除节点的迭代器失效。

删除偶数的常用写法：

    for (auto it = numbers.begin(); it != numbers.end();)
    {
        if (*it % 2 == 0)
            it = numbers.erase(it);
        else
            ++it;
    }

### 2.3 list 的迭代器移动

`list` 支持双向迭代器，可以向前和向后移动。

- `++it`：移动到下一个元素。
- `--it`：移动到上一个元素。
- `std::next(it)`：返回向后移动后的迭代器。
- `std::prev(it)`：返回向前移动后的迭代器。

使用 `std::next()` 和 `std::prev()` 需要包含 `<iterator>`。

由于 `list` 不支持随机访问，因此不能使用 `numbers[2]` 或 `it + 2`。

### 2.4 vector 与 list 的区别

| 对比 | vector | list |
|---|---|---|
| 底层结构 | 连续内存 | 双向链表 |
| 随机访问 | O(1) | O(n) |
| 尾部插入 | 均摊 O(1) | O(1) |
| 已知位置插入 | 可能移动后续元素 | O(1) |
| 已知位置删除 | 可能移动后续元素 | O(1) |
| 插入导致迭代器失效 | 取决于位置和是否重新分配 | 不影响已有迭代器 |
| 删除导致迭代器失效 | 被删除位置及其后面的迭代器失效 | 仅被删除节点的迭代器失效 |

注意：`list` 虽然在已知位置插入和删除时具有优势，但寻找插入或删除位置仍可能需要 O(n) 时间。不能简单认为 `list` 的整体性能一定优于 `vector`。

## 3. 三个实验

### 实验一：list 基础操作

创建整数链表，练习头部插入、尾部插入、遍历以及访问首尾元素。

### 实验二：list 插入与删除

完成以下操作：

- 查找并保存指定元素的迭代器。
- 在指定位置插入元素。
- 删除指定节点。
- 验证插入其他节点后，原有迭代器仍然有效。
- 使用 `erase()` 的返回值删除所有偶数。

### 实验三：vector 与 list 对比

分别创建 `vector` 和 `list`，保存指向 30 的迭代器，在 20 前插入 15，再删除 30。

实验中发现：

- `list` 插入节点后，原来的 30 迭代器仍然有效。
- `vector` 插入节点后，原来的 30 迭代器失效。
- `vector` 需要重新遍历获取 30 的迭代器，才能安全删除。
- 两种容器最终都得到相同结果。

最终输出：

    vector: 10 15 20 40 50
    list: 10 15 20 40 50

## 4. 本日总结

Day11 重点不是记住 `list` 的 API，而是理解它与 `vector` 的底层结构差异。

`vector` 适合频繁随机访问、顺序遍历以及尾部添加元素的场景；`list` 适合已经拥有目标位置迭代器、需要频繁在中间插入或删除节点的场景。

实际开发中，应根据访问方式和操作特点选择容器，而不是只看插入、删除的时间复杂度。
